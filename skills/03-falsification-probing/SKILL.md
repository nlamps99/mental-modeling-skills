# 03 - Falsification Probing（反例证伪与红队压力测试）

## 核心背景与认知原理

- **反例推理理论（Johnson-Laird, 1983）**：普通人和顶尖专家的真正差距，不在于谁能找到更多支持自己的证据（确认偏误），而在于谁更善于主动搜索“反例（Counterexamples）”。
- **概念转变理论（Posner et al. / Piaget）**：心智模型的进化，必须经历“认知失衡（Cognitive Dissonance）”与“顺应（Accommodation）”。只有当旧模型被反例无情推翻时，大脑才会重新修补边界。

本技能让 AI 扮演世界上最苛刻的“红队找茬员（Red Teamer）”，对用户构建的初步模型进行极限施压，寻找断裂点。

## 何时使用

- 刚搭建了一个初步认知模型，觉得“说得很通”，需要验证其真实有效性时
- 想要明确某个思维模型的适用边界、避免教条主义时
- 准备将模型应用到高风险决策前，做破坏性压力测试（Destructive Testing）

## 工作流程

1. **用户输入大白话理解**：将自己对系统因果的理解草图输入。
2. **AI 红队全方位找茬**：
   - 寻找真实发生过的反直觉历史案例。
   - 寻找临界条件下的系统突变点（如非线性拐点）。
   - 识别未被考虑的隐蔽变量。
3. **架构修补与边界标记**：根据反例调整原有假设，标记该模型的“失效禁区”。

## 核心 Prompt 模板

```markdown
你是一位极具批判精神的红队审查员（Red Team Reviewer）和证伪主义学者。
这是我对【某某领域】核心机制与相互关系的理解模型：
--------------------------------
【在此粘贴你用大白话总结的因果模型与核心假设】
--------------------------------

请严格禁止给出赞同、客套或迎合性的夸奖。请直接发起破坏性压力测试（Destructive Testing）：

1. 【极端反例打击】：请提供 3 个历史上或真实业务中发生过的极端案例或反直觉现象，是我的这个模型完全无法解释、甚至推导结论与事实彻底相反的。
2. 【隐蔽变量揭露】：在我的因果链条中，我忽略了哪一个致命的“暗物质变量”？当这个变量波动时，整个系统的因果箭头会如何直接反转？
3. 【失效边界勘定】：请帮我划定红线——我的这个模型只能在什么样的严格前提下有效？一旦越过哪个临界值，使用这个模型就会带来灾难？
```

## 输出检查清单

- [ ] 是否给出了真实存在、不可否认的反例事实？
- [ ] 是否指出了模型隐含的前提假设盲区？
- [ ] 是否帮助用户明确了“何时不能用这个模型”的警示红线？
